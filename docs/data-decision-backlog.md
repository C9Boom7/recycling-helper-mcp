# Data Decision Backlog

이 문서는 데이터셋 설계에서 애매한 판단이 필요한 항목을 모아두는 큐다. 매번 사용자에게 바로 묻지 않고, 열린 결정이 10건 이상 쌓였을 때 조율 세션에서 한 번에 확인한다.

## Policy

- 대상: 품목을 별도 항목으로 둘지 별칭/조건으로 흡수할지, 지역/수수료 데이터를 어느 범위까지 구조화할지 같은 데이터 모델 판단.
- 기록 방식: 열린 결정은 `Open Decisions`에 추가하고, 출처/후보/추천안을 함께 적는다.
- 사용자 확인 시점: 열린 결정이 10건 이상이면 조율 세션이 사용자에게 묶어서 확인한다. 10건 미만이고 작업을 막지 않는 낮은 시급도 결정은 사용자에게 바로 묻지 않는다.
- 즉시 질문 대상: 원격 push/PR/배포, 큰 리팩터링, 위험한 삭제, 보안/개인정보/운영 영향, 제품 범위·데이터 모델을 크게 바꾸는 결정, 또는 합리적인 기본값 없이 다음 작업이 막히는 결정.
- 낮은 시급도 처리: 품목 분리/별칭 흡수, 지역·수수료 세부 범위, 출처가 애매한 후보처럼 진행을 막지 않는 판단은 `Open Decisions`에 쌓고 추천안을 남긴다.
- 결정이 내려진 항목은 `Resolved Decisions`로 옮기고, 후속 작업 세션에 배정한다.
