## 확인된 것

- **Phase 3 위젯이 Preview에서 정상 렌더링된다.** 제목·캡션·결론·번호 단계·주의·근거 순서가 카드로 그대로 나온다. 카카오가 상단에 `Kakao Tools · 재활용척척` 라벨을 자동으로 붙인다 (`status` 자동 추가 규칙대로).
- **Phase 1 자모 오타 매칭이 실사용 경로에서 동작한다.** "패트병" → 페트병.
- **Phase 2 데이터가 반영된 서버가 응답한다.** 위젯이 나온다는 것 자체가 `-kakaotools` 서버(272개) 응답이라는 증거다. 구버전 서버에는 위젯이 없다.
- ChatGPT가 카드를 그대로 두고 아래에 짧은 답변을 덧붙인다. 카드와 텍스트가 충돌하지 않았다.

## R3 오라우팅 — 원인과 조치 (R2 튜닝 1회차)

"강남구 사는데 침대 어떻게 버려?"는 품목 배출 질문인데 `get_region_disposal_info`로 갔다.
답 자체는 정확했다 — 침대 프레임/매트리스 별도 신고, 강남구청 링크까지. 다만 두 가지를 잃었다.

1. **위젯이 안 나온다.** 지역 툴은 텍스트 응답이라 카드 브랜딩이 빠진다. 확정 매칭이었다면 Phase 3 카드가 나왔어야 한다.
2. **수수료가 빠졌다.** "싱글/슈퍼싱글/퀸/킹 중 어떤 침대인지 알려주면 수수료까지 확인해줄게"로 한 턴을 더 요구했다.
   Phase 3 R2-1은 지역이 주어지면 카드에 수수료 1줄을 싣도록 설계했는데, 그 경로를 타지 못했다.

원인은 두 description의 트리거가 겹친 것이다. `get_region_disposal_info`가 **"Use when the user names where they live"**로 시작하고
예시에 `'우리 동네 폐건전지 어디 버려?'`라는 **품목 배출 질문**이 들어 있어, "강남구 사는데 + 품목" 형태를 지역 툴로 끌어갔다.

조치 (이번 커밋):

- `get_region_disposal_info`: 트리거를 "지역 자체가 질문일 때"로 좁혔다. 품목 배출 질문에 지역이 스쳐 지나가듯 언급되면
  `get_disposal_steps`에 region으로 넘기라고 명시했다. 오해를 부르던 `'우리 동네 폐건전지 어디 버려?'` 예시는 `'우리 동네 분리수거 어떻게 해?'`로 교체.
- `get_disposal_steps`: "사는 곳을 같이 말해도 이 툴을 쓰고 region으로 넘기라"는 문장과 `'강남구 사는데 침대 어떻게 버려?'` 예시를 추가.

description 길이는 각각 533자·648자로 규격(1,024자) 안이다. `pnpm local:test` 통과.
**재배포 후 R3를 다시 돌려 위젯 + 수수료 줄이 나오는지 확인해야 한다.**

## 미해결 — A1 툴 호출 여부 판별

`컵` 발화에서 툴이 호출됐는지 확정하지 못했다.

- 카카오가 붙이는 `Kakao Tools · 재활용척척` 라벨은 **위젯 응답에만** 나타난다. ambiguous는 텍스트 응답이라 라벨이 없고, 라벨 부재는 미호출의 증거가 되지 못한다.
- 개발자 콘솔의 `Tool call` 카운터는 임시 등록본에서 0으로 고정돼 있다. 위젯이 3번 렌더링된 뒤에도 0이라 집계에 반영되지 않는 것으로 보인다. 판별 근거로 쓸 수 없다.
- 서버의 ambiguous 응답은 후보를 7개 준다: 플라스틱 컵, 깨진 유리컵, 종이컵, 컵라면 용기, 컵홀더, 실리콘 컵, 머그컵. ChatGPT는 3개(유리컵/플라스틱컵/종이컵)만 제시했다. 요약했을 수도, 자체 지식으로 답했을 수도 있다.

**판별 방법**: 같은 발화를 다시 넣고 후보에 `컵홀더`나 `컵라면 용기`가 언급되는지 본다. 일반 상식으로는 컵 되묻기 선택지에 나오지 않는 항목이라, 언급되면 툴 호출이 확실하다.
