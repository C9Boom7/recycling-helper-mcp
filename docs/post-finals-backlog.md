# 본선 이후 과제 (기록 전용)

본선 기간에는 손댈 수 없거나, 마감 대비 이득이 작아 미뤄둔 항목을 한곳에 모았다.
**이 문서의 항목은 본선 마감 전에 착수하지 않는다.** 나중에 다시 잡을 때 근거를 찾아 헤매지 않도록 남기는 기록이다.

시한을 다시 적어두면 — 8/23 개발 완료, 8/27 코드 프리징, 8/31~9/28 본선. 프리징 이후에는 심각한 오류만 협의 후 고칠 수 있다.
그래서 아래 항목 중 "운영 중 자동 갱신" 성격은 이번 사이클에 넣어봐야 작동할 수 없다.

## 1. 텍스트 폴백 응답 크기 — 런타임 필터링

`WIDGET_ENABLED=false` 경로에서 매트리스 응답이 5.7KB까지 커진다. `formatBulkyWasteFeeLines`가 (지역, 품목)의 12행을 고시명까지 붙여 전부 나열하고, 매트리스는 고시명 자체가 길다.

- **본선에 영향 없다.** 실사용 경로인 위젯은 `수수료 500원~10,000원 (규격 12종)`으로 요약해 1.5~1.8KB에 머문다.
- 미룬 이유: 고치려면 런타임 렌더링에 필터를 넣어야 하는데, Phase 6·7이 **런타임 코드 무변경**을 전제로 데이터를 넣었고 8/21 기능 변경 마감에도 걸린다.
- 재개할 때 방향: 데이터를 더 자르지 말고 렌더링에서 줄인다. (지역, 품목) 행 상한을 6에서 12로 올린 결정이 이미 "데이터는 남기고 표시를 줄인다"는 쪽이었다.
- 근거: [phase-7 PRD의 "응답 크기"](prd/phase-7-bulky-item-fee-expansion.md), [phase-6 PRD](prd/phase-6-bulky-fee-etl.md)의 12행 상한 결정.

### 곁들여 정리 — Phase 1의 2.0~2.2KB 예산은 어디서 나온 값인가

본선 가이드에는 응답 크기의 숫자 상한이 없다. 가이드가 요구하는 건 "result 크기 최소화"와 "API 원본 덤프 금지"뿐이다.
2.0~2.2KB는 **당시 대표 확정 매칭 응답을 실측한 값**(text 1.5~1.7KB + structuredContent 약 0.5KB)이고,
Phase 1은 폴백 응답이 "그 대표 응답과 같은 자릿수를 유지한다"는 상대 기준으로 이 숫자를 썼다([phase-1 PRD](prd/phase-1-matching-fallback.md) 6번·109줄).

즉 **넘으면 규격 위반이 되는 절대선이 아니라, 폴백이 확정 매칭보다 뚱뚱해지는 걸 막으려고 세운 기준선**이다.
텍스트 폴백 5.7KB를 "규격 초과"가 아니라 "기준선 이탈"로 읽어야 하는 이유가 여기 있다. 실사용 경로가 위젯인 이상 본선 심사에는 걸리지 않는다.

## 2. 조례 개정 상시 감지

자치법규 API의 `시행일자`만 주기적으로 확인하면 조례 개정을 자동으로 잡을 수 있다.

- 미룬 이유: 프리징 이후에는 개정을 감지해도 고칠 수 없다. 감지 장치만 남고 대응 경로가 없다.
- 이번 사이클에서 대신 하는 것: Phase 6 R5의 **출고 직전 1회 확인**. 상시 갱신이 아니라 스냅샷 최신성 점검이다.
- 재개할 때 방향: 감지와 함께 "데이터만 고쳐 재배포하는" 경로가 살아 있는 시기에 붙여야 의미가 있다.

## 3. 기후에너지환경부 분리배출 API

- 상태: `serviceKey` 발급에 계정이 필요해 응답 스키마조차 확인하지 못했다. 등록 공간범위가 "서울"이고 오퍼레이션은 `getSpot` 하나다.
- 미룬 이유: 마감 전에 새 외부 의존을 들이는 이득이 불확실하다.
- 재개할 때 방향: 키를 받으면 응답 스키마만 확인해 기록하고, 실제 활용 여부는 그다음에 판단한다.

## 4. 동작구 별표 파서

Phase 6 R1의 추출 스크립트가 10곳 중 9곳의 행 파싱까지 성공했고, 동작구만 열 구성이 달라 보류 중이다.

- 미룬 이유 그 자체는 아니다 — 본선 마감 전에는 **수작업 입력으로 메울 수 있는 규모**라 파서 지원이 급하지 않다는 뜻이다.
- 재개할 때 방향: 지자체 별표는 조판이 제각각이라 한 파서로 전부 처리하려 들지 말고 형태별로 붙인다는 원칙을 유지한다.

## 5. 대형폐기물 수수료의 상시 최신성

조례 금액과 실제 부과액이 항상 같지는 않다. 조례가 상한이나 기준을 정하고 실무는 구청 고시를 따르는 경우가 있다.

- 이번 사이클의 대응: 골든셋 4곳 대조로 표본 검사를 겸하고, 응답에는 "수수료 후보"라는 표현과 신청 URL을 함께 내보낸다. 규격 판정은 결국 접수 담당자가 한다.
- 재개할 때 방향: 불일치가 잦은 것으로 드러나면 `feeUrl`(구청 페이지)을 우선 근거로 올리고 조례를 보조로 내린다.

## 6. 운영 등록본 서버 교체

PlayMCP 운영 등록본이 아직 구버전 서버를 가리킨다. **사용자가 직접 나중에 바꾼다.** 개발 세션은 건드리지 않는다.
예선 서버(`recycle-helper-mcp`, ID 1498)는 어떤 경우에도 손대지 않는다.
