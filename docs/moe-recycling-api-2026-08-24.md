# 기후에너지환경부 분리배출 정보조회 API — 실측과 활용 판단 (2026-08-24)

[본선 이후 과제 5번](post-finals-backlog.md)의 후속이다. 2026-08-24에 인증키를 받아 두 오퍼레이션을 실제로 불러 보고,
그쪽 품목 사전을 전부 긁어 우리 카탈로그와 대조했다. 원문과 대조 결과는 `logs/moe-api/`(gitignore)에 있고
아래 명령으로 다시 만들 수 있다.

```bash
node scripts/probe-moe-recycling-api.mjs item --enumerate     # 그쪽 사전 전수 수집 → logs/moe-api/catalogue.json
pnpm build && node scripts/compare-moe-catalogue.mjs          # 우리 매처로 대조 → logs/moe-api/compare.json
node scripts/probe-moe-recycling-api.mjs spot --addr 역삼동 --rows 1000
node scripts/probe-moe-recycling-api.mjs spot --lat 37.4979 --lng 127.0276 --radius 500
```

인증키는 저장소 루트 `.env`에서 읽는다(값은 커밋하지 않는다). 개발계정 한도는 하루 10,000건.

## 한 줄 요약

- **getItem은 공식 품목 사전 767개다.** 우리 매처에 넣으면 **절반(385)만 확정**되고 358개는 `not_found`다. 확정된 것 중 17개는 배출 갈래가 우리와 다른데, 그중 9개는 **우리 매처의 과매칭**이고 6개는 **정책 차이**다. 둘 다 지금 고칠 가치가 있다.
- **getSpot은 문서와 달리 전국이고, 종량제봉투 판매소뿐 아니라 폐의약품·폐건전지·형광등·의류·폐휴대폰·투명페트병 수거처까지 준다.** 동 이름(법정동) 또는 좌표+반경으로 찾고, 1,000건을 한 번에 300~500ms에 받는다. "근처 수거함 어디?"에 답할 재료로는 충분한데, 우리 툴이 위치를 받는 자리가 없고 외부 호출이라 본선에 넣으려면 8/29 게이트와 장애 대비를 같이 봐야 한다.

## 1. getItem — 품목 사전

### 1-1. 스키마와 동작

| 항목 | 실측 |

### 1-4. 런타임에 부를 수 있나

- 지연 30~130ms라 p99 3,000ms 예산 안에 넉넉히 든다. 일 10,000건 한도도 본선 트래픽에는 남는다.
- 그러나 답이 **라벨 하나**라 그대로 내보낼 수 없다. `종량제봉투`를 받으면 우리 쪽 재질 안내로 바꿔 써야 하는데, 그 변환표를 만들 거면 **767개를 아예 데이터로 들여오는 편이 낫다.** 사전이 작고(767행) 하루면 전부 받을 수 있으며, 그러면 외부 의존·키 관리·장애 처리가 런타임에서 사라진다.
- 결론: **런타임 호출은 안 한다. ETL로 쓴다.**

## 2. getSpot — 분리배출 장소

### 2-1. 스키마와 동작

| 항목 | 실측 |
| --- | --- |
| 요청 | `addr` 주소 검색어 **또는** `latitude`·`longitude`·`radius`(m). 둘 다 주면 둘 다 만족해야 해서 `addr=강남역`+좌표는 NODATA |
| `addr` | 주소 문자열 **부분일치**. 법정동 이름은 된다(`상계동` 524, `역삼동` 343, `문래동` 50). 행정동(`상계1동`)·구(`강남구`)·시(`서울`)·역(`강남역`)·지명(`해운대`)은 전부 NODATA. 동음 오염이 있다 — `우동`은 화성 `석우동`, `좌동`은 창원 `여좌동`, `서교동`은 마포 95건에 여수 9건이 섞인다 |
| 좌표 | 강남역 반경 500m → 66건, 3km → 2,011건. 첫 행이 반경과 무관하게 같아 **가까운 순 정렬**로 보인다 |
| 응답 | `spotNm` 장소명, `addrBase` 기본 주소, `addrDtl` 상세 주소. **그뿐이다** — 문서에 적힌 경위도 좌표는 안 온다. 장소 종류 필드도 없어 `spotNm` 문자열로 갈라야 한다 |
| 종류 필터 | 파라미터 없음. `numOfRows=1000`으로 한 번에 받아 쪽에서 거른다 |
| 지연 | 270~540ms (1,000행 기준) |
| 공간범위 | **전국.** 문서의 "대한민국 서울"은 틀렸다 — 여수·화성·울산·창원이 나왔다 |

실측 최대 행 수는 상계동 524행이라 1,000행 상한 안이다.

### 2-3. 쓸 수 있는 모양

- 우리 `region-policies.json`은 "폐건전지는 주민센터 수거함"처럼 **어디 종류인지**까지만 말한다. getSpot은 **어느 주소인지**를 준다. 겹치는 게 아니라 한 단계 더 내려가는 정보다.
- 질문 모양은 "상계동 사는데 폐의약품 어디 버려?"다. 동을 말하면 `addr` 한 번(300~500ms)으로 받아 `spotNm`을 묶음표로 거르고 주소 3~5개를 돌려주면 된다. 좌표는 카카오 호스트가 넘겨주지 않으니 `addr` 경로만 현실적이다.
- 걸리는 것: ① 동을 **법정동**으로 받아야 한다 — 사용자가 행정동(`상계1동`)을 말하면 `상계동`으로 줄이는 처리가 필요하고, 동음 오염은 응답 주소의 시·구로 한 번 더 걸러야 한다. ② 응답에 좌표가 없어 거리순 정렬은 서버(그쪽) 순서를 믿는 수밖에 없다. ③ **외부 호출**이다 — 키를 배포 환경변수로 넣을 수 있는지(PlayMCP in KC), 장애 시 "지자체 안내로 확인"으로 내려앉는 폴백, 호출 로그가 필요하다. ④ 툴 입력에 동/주소를 받는 자리가 없어 **툴 계약 변경**이다 — 새 툴이든 `get_region_disposal_info` 확장이든 8/29 기능 변경 마감 안에 머지·재배포·Preview까지 끝내야 하고, 9/14 프리징 뒤 API가 죽어도 못 고친다.

## 3. 권고

우선순위 순이다. 1·2는 데이터 작업이라 게이트와 무관하고, 3·4는 런타임·계약 변경이라 8/29 전에 끝낼지 본선 이후로 둘지 사람이 정한다.

1. **과매칭 9개를 고친다(지금).** 전부 "그쪽 이름 → 우리 엉뚱한 품목"이 재현되는 구체 사례라 별칭·가드·회귀 케이스로 바로 옮길 수 있다. 되묻기 24개는 반례 세트로 넣는다.
2. **정책 차이 6개를 출처 열어 판정한다(지금).** 가위·벤토나이트 모래·주사기·인슐린주사기·전기비데·칫솔살균기. 우리가 맞을 수도 있다 — 기록만 남겨도 된다.
3. **767개 사전을 데이터로 들여와 `not_found` 폴백의 한 층으로 쓴다(런타임 변경, 8/29 전 또는 본선 이후).** `src/data/moe-item-dictionary.json`(품목명·라벨·확인일·출처 URL)을 두고, 우리 매처가 `not_found`일 때 이 사전에서 부분일치로 찾아 "공식 분리배출 사전은 이 품목을 `종량제봉투`로 안내합니다"처럼 **라벨과 출처만** 답한다. 라벨 → 우리 재질 안내(`material-guidelines.json`) 연결은 라벨이 32종뿐이라 표 하나로 끝난다. 공식 사전 기준 커버리지가 50% → 사실상 100%가 되고, 외부 호출은 없다. 단 `not_found` 경로(`unknownItemResult`)를 건드리는 런타임 변경이라 Phase 10과 같은 게이트에 걸린다.
4. **getSpot은 본선 이후로 둔다(권고).** 가치는 분명하지만 ③·④가 걸린다 — 외부 의존을 프리징 직전에 들이고 9/16~10/12 사이 장애가 나면 손을 못 댄다. 본선 이후에 `find_nearby_disposal_spot`(동·품목 → 주소 목록) 툴로 붙이고, 그때 키 관리·폴백·법정동 정규화를 같이 설계한다. 그래도 본선에 넣겠다면 8/27까지 PR 리뷰 완료라는 Phase 10과 같은 조건을 건다.
