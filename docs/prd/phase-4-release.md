# Phase 4 — 발화 테스트·튜닝·마감 (마감 8/23)

## 목표

Kakao Tools Preview에서 실사용 시나리오를 돌려 **툴 호출률과 답변 품질을 실측**하고, description·응답을 튜닝한 뒤 8/23 개발 완료를 선언할 수 있는 상태로 마감한다.

당초 8/21~23을 잡았던 일정이지만, Phase 1~3이 조기에 머지되면 전제만 갖춰지는 대로 앞당겨 착수한다.

## 전제

- Phase 0~3이 PR 머지로 main에 반영되어 있고, 사용자 재배포 클릭으로 본선 서버에 올라간 상태.
- Preview 테스트는 Claude가 Chrome 확장으로 대행한다. 필요 조건: Chrome에 카카오 계정(PlayMCP 가입 계정) 및 ChatGPT 계정(Plus/Pro 권장, Business/Enterprise 불가) 로그인 유지.
- Preview 사용 시 참고 (가이드 §4): 도구함에는 테스트할 MCP만 담는다. 실제 툴 이름에는 MCP 식별자 prefix가 붙는다. 위젯 확인 후에는 "새 대화 시작"으로 초기화한다. 툴 호출은 비결정적이므로 시나리오당 필요 시 2회까지 반복한다.

## 4a — 배포·연결 검증 (Phase 0 배포 직후, 최우선)

발화 테스트(4b)에 앞서 배포 사이클을 한 번 완주해 인프라를 검증한다. 여기서 막히면 이후 작업이 전부 무의미하다.

1. 사용자에게 재배포 클릭을 요청하고 Active 전환을 확인한다.
2. 본선 endpoint(`-kakaotools`가 붙은 쪽)로 `initialize`/`tools/list`가 통과하는지 확인한다 — 예선 서버(ID 1498)는 건드리지 않는다.
3. Kakao Tools Preview에 MCP를 연결하고, 툴 5개가 prefix 붙은 이름으로 노출되는지 확인한다.
4. 직접 발화 1~2개로 툴 호출과 위젯 렌더링(Phase 3 R6의 이관분)을 확인한다.

4a까지는 배포 확인이 목적이므로, 결과 기록은 간단한 메모면 충분하다. 이후 요구사항(R1~R4)이 4b다.

## 요구사항

### R1. 발화 테스트 매트릭스

`docs/preview-test-plan.jsonl`로 작성·관리 (`logs/`는 예시 파일 외에 gitignore 대상이라 커밋이 안 된다 — 테스트 계획·결과는 합성 데이터라 버전 관리한다). 최소 25개 시나리오, 카테고리별:

| 카테고리 | 예시 | 확인 포인트 |
| --- | --- | --- |
| 직접 발화 (5) | "기름 묻은 피자박스 어떻게 버려?" | get_disposal_steps 호출 + 정답 |
| 판단형 (4) | "스티로폼 재활용 돼?" | classify 또는 steps 호출 |
| 오타/변형 (4) | "패트병 라벨 떼야돼?" | Phase 1 자모 매칭 동작 |
| 미등재 (3) | "실리콘 뒤집개 버리는 법" | Phase 1 폴백이 유용한 답으로 이어짐 |
| 포괄어 (2) | "컵 어떻게 버려?" | ambiguous → ChatGPT가 되물음 |
| 다품목 (2) | "이사가서 침대랑 화분이랑 옷 버려야 해" | make_cleanup_plan 호출 |
| 지역 (3) | "강남구 대형폐기물 신고 어떻게 해?" | region 툴 + 수수료/링크 |
| 비의도 (2) | "오늘 저녁 뭐 먹지" | 툴이 호출되지 **않아야** 함 (과호출 점검) |

기록 항목: 발화, 호출된 툴(없음 포함), 답변 요약, 위젯 렌더링 여부, 판정(pass/fail), 메모.
결과는 `docs/preview-test-results-<날짜>.md`로 남긴다.

### R2. 튜닝 루프

- 툴 호출 누락 패턴 → description 발화 예시 보강 (Phase 0 R3 규칙 유지: 1,024자 이내).
- 오라우팅(엉뚱한 툴 호출) → 툴 간 경계 문구 조정.
- 답변 품질 문제 → 해당 Phase 산출물(폴백 문구, 데이터, 위젯)에 피드백.
- 루프당: 수정 → `pnpm local:test` → 브랜치 push + PR → 사용자에게 머지 지시·재배포 클릭 요청 → Preview 재측정. (README의 Git 워크플로를 따른다 — 로컬 main 머지·직접 push는 쓰지 않는다.) **재배포 횟수를 아끼기 위해 수정은 묶어서 배포한다** (하루 1~2회).

### R4. 마감 게이트

- 8/21까지: 기능 변경 마감 (이후 발화 테스트 기반 문구·데이터 수정만). Phase 5의 표준 티어 지역 데이터 추가는 여기서 말하는 "데이터 수정"에 포함한다 — 단 스키마·코드 변경 없이 검증을 통과하는 데이터만.

## 검증 및 완료 기준 (DoD)

1. 25개 시나리오 중 의도 발화의 툴 호출률 ≥ 80%, 비의도 발화 과호출 0.
2. 오답/무용답 시나리오 0 (폴백 포함 모든 응답이 "다음 행동이 가능한" 답).
3. R3 문서 4종 완료 — README, `docs/prd/README.md` 진행 상태 표, `docs/qa-runbook.md`, `docs/preview-test-results-<날짜>.md`(p99 측정 기록 포함).
4. 최종 상태가 본선 서버에 배포·확인됨.
