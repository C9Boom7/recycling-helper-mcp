# Local MCP Workflow

재활용척척은 평소에는 로컬에서 충분히 검증하고, 큰 개선이나 제출 전 확인이 필요할 때만 PlayMCP in KC에 새 서버를 올린다.

## 기본 원칙

- 데이터, 답변 포맷, MCP 도구 변경은 먼저 로컬에서 검증한다.
- PlayMCP in KC는 원격 호환성, 등록 화면, 심사 전 시연 확인용으로 사용한다.
- 기존 PlayMCP 서버의 `중지`/`시작`은 컨테이너 프로세스 재시작일 뿐, Git `main` 최신 커밋으로 재빌드되지는 않는다.
- PlayMCP에 새 코드를 반영해야 할 때는 새 Git 소스 빌드 서버를 만들거나 기존 서버를 삭제 후 다시 생성한다.

## 지역 안내 노출 정책

`region_review_needed`는 데이터 검수 상태이지, 모든 답변에서 강한 지역 확인 문구를 내보내라는 뜻은 아니다.

- `필수`: 전용 수거함, 지정 수거처, 대형폐기물 신고·수수료, 불연성·특수규격 봉투, 가스·폭발·유해폐기물처럼 지역 기준이 실제 배출 방식을 바꾸는 품목은 `### 지역 확인 필요`와 공식 지역 출처를 유지한다.
- `참고`: 기본 배출 판단은 전국 기준으로 충분하고 실제 배출 요일·장소만 지역에 맞추면 되는 품목은 `### 지역 참고` 한 줄로 낮춘다. 특정 지역 item guide가 있는 경우에만 해당 지역 세부 안내와 공식 출처를 붙인다.
- `낮음`: 칫솔, 고무장갑, 샤프심처럼 지역 정보가 답변 정확도를 거의 바꾸지 않는 품목에는 지역 섹션과 지역 공식 출처를 붙이지 않는다.

회귀 테스트에서는 우산처럼 `region_review_needed`이지만 안내가 과하면 품질이 떨어지는 품목에 `서울 강남구 공식 출처` 제외 조건을 둔다. 반대로 폐건전지, 폐의약품, 소형가전, 대형폐기물, 가스류는 강한 지역 확인을 유지한다.

## 로컬 검증 명령

```bash
pnpm check
```

`pnpm check`는 TypeScript 타입 검사, 데이터 스키마 검증, 대표 질문 평가를 실행한다.

```bash
pnpm smoke:mcp
```

`pnpm smoke:mcp`는 빌드 후 로컬 MCP 서버를 임시 포트로 띄우고 실제 Streamable HTTP 요청을 보낸다.
답변 품질 회귀 케이스는 `src/data/mcp-answer-cases.json`에서 관리한다.

확인하는 대표 회귀 포인트:

- `/health`의 품목 수가 `src/data/waste-items.json`의 품목 수와 일치하는지

- `책상의자 + 서울 강남구` 답변에 대형폐기물 수수료 후보가 포함되는지

```bash
pnpm local:test
```

`pnpm local:test`는 `pnpm check`와 `pnpm smoke:mcp`를 연달아 실행한다. PlayMCP에 올리기 전 기본 게이트로 사용한다.

로컬 테스트 중 답변이 애매하거나 품목이 비어 있는 질문을 발견하면 `src/data/question-backlog.json`에 먼저 추가한다.
백로그 요약은 다음 명령으로 확인한다.

```bash
pnpm backlog:questions
```

수동 테스트 질문이나 실제 사용자 질문 로그가 쌓이면 자동 후보 생성을 먼저 dry-run으로 확인한다.

```bash
pnpm log:query -- --query "요가매트는 어떻게 버려?" --region "서울 강남구" --answer "bad_match"
pnpm backlog:auto -- --input logs/manual-queries.jsonl --region "서울 강남구"
pnpm backlog:auto -- --input logs/manual-queries.jsonl --region "서울 강남구" --write
```

`pnpm log:query`는 실제 질문 로그를 `logs/manual-queries.jsonl`에 JSONL로 남긴다. 이 파일은 Git에 커밋하지 않는다.
`pnpm backlog:auto`는 매칭 실패, 낮은 매칭 점수, `needs_source`, 낮은 confidence 품목을 `todo` 후보로 만든다. 저장 후에는 `pnpm backlog:questions`와 `pnpm check`를 실행한다.

## PlayMCP에 올릴 기준

다음 중 하나에 해당할 때만 PlayMCP in KC 원격 테스트를 진행한다.

- MCP 도구 스키마, 도구 개수, 서버 transport 동작이 바뀐 경우
- Top 품목 데이터가 크게 늘거나 지역 정책 구조가 바뀐 경우
- 심사 제출 전 실제 endpoint 기준으로 최종 점검해야 하는 경우
- 로컬 smoke는 통과하지만 PlayMCP 등록/호출 호환성이 의심되는 경우

PlayMCP에 올린 뒤에는 다음을 확인한다.

```bash
curl -sS https://<endpoint-host>/health
```

최신 데이터가 반영된 서버라면 `items`가 `src/data/waste-items.json`의 품목 수와 일치해야 한다.
